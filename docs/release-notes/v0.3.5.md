This release contains 13 new features, 12 bug fixes, and 12 other changes.

### New Features

- [dsh-perf] The performance engine ships for the first time as a built-in plugin: DSH Web performance observation and governance (HUD, alerting, write-batch throttling, render offloading, subagent storm alerts, idle observation, and settings cards)
- [dsh-perf] Session-list publish gating (projection flushes merged to 1Hz) plus a stream-forward cooldown experiment (off by default)
- [dsh-perf] Sidebar session-row content-visibility offloading (large better-sidebar group expansion)
- [git-graph] Git worktree parallel sessions (blank-session branch selector plus Git graph)
- [task-board] Drag and drop to move cards between manual columns
- [skin-center] User skin uninstall and integrity verification with auto-repair
- [market] Workshop install counts and per-plugin npm downloads
- [market] Two-level plugin subcategory filtering
- [market] Drop the decorative artwork placeholder on plugin cards
- [telemetry] Paginated dark dashboard for tv.dsh-market.com
- [pet] Murmurs follow session context and the current session
- [remote-web-ui] Manual pairing token input on the fence screen
- [community] Register dsh-mcp-manager and dsh-provider-usage in the community plugin index

### Bug Fixes

- [task-board] Never close the board implicitly on session-list churn
- [task-board] Resolve navigation jitter, skin scrim clobber, and document the desktop profile
- [skin-center] Restore legacy market skin hooks
- [skin-center] Reduce orca-link session-switch latency
- [orca-link] Fix the orca-link chain problem (mount binding scope)

Compatibility: this release passed the automatic-upgrade compatibility audit (package identity, profile writes, persisted identifiers, wire protocol, and cross-platform lifecycle compared between v0.3.4 and v0.3.5); no blocking changes were found. Every existing package keeps its npm name, exports, bundle patch, and settings ids byte-for-byte. Persisted identifiers are frozen: no existing localStorage key, settings section id, API path, or profile/bundle row was removed or renamed — all new keys (dsh-perf-css, dsh-perf-stream-cooldown, dsh-perf-debug) belong to the new built-in plugin, and all new API endpoints (/api/skin-center/v2/verify, /skins/:id/uninstall, /skins/:id/repair) are additive. The skin manifest v2 schema is unchanged. dsh-perf now mounts inside the aggregate: its patch replaces the official session-persistence-jsonl row config as a whole (writeBatchMaxDelayMs 200→500ms) while restating every key the base row owns, verified against the official schema defaults; the plugin row itself is enabled with the same defaults as a standalone install (meter 2000ms, window 120s).

The legacy aggregate @linxin666/dsh-web-ui-all dual-publish window ended with this release: v0.3.5 is the final dual-published version (v0.3.3/v0.3.4/v0.3.5 carry dsh.migrate metadata); the legacy name is now deprecated with a migration notice and future releases stop publishing it. Automatic migration of legacy profiles uses the deterministic map in shared/host/legacy-migration.ts, consistent between plugin-manager and Doctor.

Doctor auto-migration keeps its previous behavior: enabled by default for dsh-doctor launch, the Doctor service launcher, and "dsh-doctor migrate"; a bare "dsh web" does not pass through the Doctor preflight.

This release validates the full local gate suite (sync-shared, typecheck, 21-workspace tests, script tests, aggregate, runtime-deps, market, skin-center), the fresh aggregate mount composition (20 rows / 18 deps), and verify-version against all 20 family packages. It does not claim a real previous-version-to-target upgrade drill or a real macOS / Windows upgrade matrix. For manual recovery of a legacy profile, back up package.json and pnpm-lock.yaml in the profile directory, then run:

```
dsh plugin --profile web add @linxin666/dsh-web-all@0.3.5
dsh plugin --profile web remove @linxin666/dsh-web-ui-all
dsh --profile web --dump-config
```

If migration fails, keep the backup and do not start a bare dsh web; repair the profile and run --dump-config again.
