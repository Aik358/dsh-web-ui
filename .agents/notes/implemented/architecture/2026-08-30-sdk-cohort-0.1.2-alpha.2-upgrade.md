# Agent Note: SDK cohort upgrade to 0.1.2-alpha.2

Status: implemented

## Problem

The DSH runtime moved to the 0.1.2-alpha.2 preview (upstream tag `dsh-v0.1.2-alpha.2`, commit 0a53fb5), and the repository had to follow while its whole `@deepseek-ai` cohort stays npm-unpublished (registry dist-tags still end at 0.1.1-rc.2). Beyond the routine version bump, alpha.2 carries two structural changes that break the repository as built against alpha.1: `dsh-settings` removed the standalone `installSettingsSection` / `settingsNamespace` / `deepEqualJson` exports in favor of the `ctx.settings` service seam, and the announced "peer dependency optimization" trimmed most sibling peers from the published manifests, which severed type-graph edges the plugins had been consuming transitively.

## Decision

The cohort store mechanism is reused unchanged in shape: `scripts/build-cohort-tarballs.mjs` now pins tag `dsh-v0.1.2-alpha.2` / commit `0a53fb55bea101816fa226bb964ae2bed71c343b`, the store lives at `~/.dsh-cohorts/0.1.2-alpha.2/` (249 tarballs), and the `overrides:` block, `minimumReleaseAgeExclude`, all manifest ranges, the CI cohort-cache paths, and the inject-contract pin all read `0.1.2-alpha.2`. Three packages the alpha.2 dependency graph newly pulls (`dsh-deque`, `dsh-util-time`, `dsh-util-values`) are added to the overrides so the family resolves entirely from the store; none may leak in from the registry.

Settings consumers (doctor, desktop-launcher, ssh, perf, pet, market, liangshen, task-board, usage, git-graph, tool-describe-image, skin-center, remote-web-ui) migrate to the official pattern: `ctx.inject(['settings'], (settingsCtx) => settingsCtx.settings.installSection(ctx, ns, schema, entry, hooks))` with the hook shape unchanged, and namespace constants become `'literal' as SettingsNamespace` so every downstream consumer keeps the branded type. The web-settings bridge passes `ns as SettingsNamespace` straight to the provider `mutate`, whose signature is otherwise unchanged.

The tool-level consequence of the peer trimming is fixed at its cause: alpha.2 manifests require `@deepseek-ai/cordis ^4.0.2` (with `cordis-plugin-loader ^1.0.3` / `cordis-plugin-include ^1.0.7`), so the repository's own declarations move to `^4.0.2` and the release-age exclusions follow (cordis 4.0.2, loader 1.0.3, include 1.0.7, cosmokit 1.8.3, schemastery 3.18.2). Without that, pnpm resolves two cordis copies (4.0.1 for the repository, 4.0.2 for the cohort) and every `declare module '@deepseek-ai/cordis'` service augmentation silently stops applying. The same trimming removed `dsh-client-ui-session` from `dsh-client-ui-conversation`'s reach, so `dsh-git-graph` — whose chip props rely on the `sessionId` / `useSessions` standard-props merge that ui-session contributes — now declares that package and pulls its client types explicitly.

`SessionEvent.ignorable` is restored upstream but the repository is unaffected: the dsh-perf migration core reads the marker off its locally typed legacy jsonl rows. The remote-web-ui cohort claims re-verified for alpha.2: nothing emits `api/gate`, and the one-stream-socket wire rules are unchanged (the contract tests pass against the new cohort unmodified).

## Alternatives considered

Re-merging peers into the store tarballs to restore the alpha.1 type-graph reach was rejected: it would fabricate packaging the official cohort deliberately dropped. Keeping cordis at 4.0.1 was rejected: the augmentation split it causes fails every package typecheck. Wrapping the settings service in a shared repository helper was rejected as a new abstraction where each package already follows the official per-plugin pattern.

## Consequences

Bundles remain dual-cohort: no alpha.2-only runtime surface is consumed, so the built plugins still load on the alpha.1 host that currently runs; switching the host itself to `dsh-v0.1.2-alpha.2` is a user-side runtime upgrade and restart. The `pnpm clean --lockfile` rebuild made lockfile `file:` paths checkout-relative, so the committed lockfile must be regenerated in the main checkout after merge (the CI store cache key changes with `pnpm-workspace.yaml` and rebuilds automatically). New type-graph edges may surface for other consumers when upstream trims more peers; the fix pattern is a declared devDependency plus an explicit type-only import.
