# Agent Note：SDK cohort 升级到 0.1.2-alpha.2

Status: implemented

## 问题

DSH 运行时推进到 0.1.2-alpha.2 预览版（上游 tag `dsh-v0.1.2-alpha.2`，commit 0a53fb5），仓库必须跟进，而整个 `@deepseek-ai` cohort 仍未发布到 npm（registry dist-tag 停在 0.1.1-rc.2）。除常规版本推进外，alpha.2 带来两个结构性变化，直接破坏按 alpha.1 构建的仓库：`dsh-settings` 移除了独立的 `installSettingsSection` / `settingsNamespace` / `deepEqualJson` 导出，改为 `ctx.settings` 服务缝；同时发布说明中的「peer dependency 优化」裁掉了清单里绝大多数兄弟 peer，斩断了插件一直在传递消费的类型图边。

## 决策

cohort store 机制原样复用：`scripts/build-cohort-tarballs.mjs` 钉住 tag `dsh-v0.1.2-alpha.2` / commit `0a53fb55bea101816fa226bb964ae2bed71c343b`，store 位于 `~/.dsh-cohorts/0.1.2-alpha.2/`（249 个 tarball）；`overrides:` 块、`minimumReleaseAgeExclude`、全部清单 range、CI cohort 缓存路径、inject 契约 pin 统一改为 `0.1.2-alpha.2`。alpha.2 依赖图新拉入的三个包（`dsh-deque`、`dsh-util-time`、`dsh-util-values`）补进 overrides，整个家族全部从 store 解析，不允许任何一个从 registry 漏进来。

settings 消费者（doctor、desktop-launcher、ssh、perf、pet、market、liangshen、task-board、usage、git-graph、tool-describe-image、skin-center、remote-web-ui）迁移到官方模式：`ctx.inject(['settings'], (settingsCtx) => settingsCtx.settings.installSection(ctx, ns, schema, entry, hooks))`，hook 形状不变；namespace 常量改为 `'literal' as SettingsNamespace`，下游消费的 branded 类型保持不变。web-settings 桥接直接以 `ns as SettingsNamespace` 调 provider `mutate`，其余签名未变。

peer 裁剪在工具链层面的后果从根因修复：alpha.2 清单要求 `@deepseek-ai/cordis ^4.0.2`（连带 `cordis-plugin-loader ^1.0.3` / `cordis-plugin-include ^1.0.7`），仓库自身声明随之升到 `^4.0.2`，release-age 排除项同步（cordis 4.0.2、loader 1.0.3、include 1.0.7、cosmokit 1.8.3、schemastery 3.18.2）。否则 pnpm 会解析出两份 cordis（仓库 4.0.1、cohort 4.0.2），所有 `declare module '@deepseek-ai/cordis'` 服务增强静默失效。同一裁剪也使 `dsh-client-ui-conversation` 够不到 `dsh-client-ui-session`：git-graph 的 chip props 依赖 ui-session 贡献的 `sessionId` / `useSessions` 标准 props 合并，因此显式声明该包并引入其 client 类型。

`SessionEvent.ignorable` 上游已恢复，但仓库不受影响：dsh-perf 迁移核心读取的是本地类型的 legacy jsonl 行上的标记。remote-web-ui 的 cohort 断言对 alpha.2 重新核实：依旧没有任何组件发出 `api/gate`，单流 socket 的 wire 规则未变（契约测试对新 cohort 原样通过）。

## 备选方案

为恢复 alpha.1 的类型图可达性而在 store tarball 里重新合并 peers——拒绝：那会伪造官方 cohort 有意裁掉的打包形态。cordis 留在 4.0.1——拒绝：增强分裂会让所有包 typecheck 失败。用仓库共享 helper 包一层 settings 服务——拒绝：各包已遵循官方 per-plugin 模式，不应新增抽象。

## 后果

bundle 保持双 cohort 兼容：未消费任何 alpha.2 独有的运行时面，构建产物仍能在当前运行的 alpha.1 宿主上加载；宿主本体切到 `dsh-v0.1.2-alpha.2` 属于用户侧运行时升级与重启。`pnpm clean --lockfile` 重建使 lockfile 的 `file:` 路径相对 checkout，因此合并后必须在主 checkout 重新生成提交的 lockfile（CI 的 store 缓存 key 随 `pnpm-workspace.yaml` 变化并自动重建）。上游继续裁剪 peer 时可能暴露更多类型图边，修复模式即：声明 devDependency 并加显式 type-only import。
