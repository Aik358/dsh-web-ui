# Agent Note: 玩法卡片改为从宠物侧面打开

Status: implemented

## Problem

玩法卡片锚在宠物脚下并向上生长覆盖精灵（`transform: translateY(calc(-100% - 20px))`），在四条属性、操作按钮和商店网格的体量下（约 180-260px 高，对比 160px 的默认精灵盒），卡片顶部会越过精灵顶点进入其上方的区域——正是会话/状态气泡栈所在的带区（以精灵为轴心居中、且有意做得较宽的气泡）。卡片与宽气泡互相遮挡，气泡盖住了卡片下部按钮（报告截图里被药丸盖住的「钱包」按钮）。此前把玩法入口并入悬浮面板的改动（[宠物玩法入口并入悬浮面板](../../bug-fix/2026-08-25-pet-gameplay-entry-hover-panel.md)）只解决了入口遮挡；这是剩余的卡片与气泡冲突，而把卡片改为向下生长同样会撞上悬浮面板。

## Decision

卡片现在改为在宠物**侧面**打开，不再向上生长。`GameplayHud` 在布局 effect 里测量父级 float 盒与自身宽度：卡片以精灵盒垂直居中、max-height 钳制在精灵高度（更高时内部滚动），侧向按剩余可用空间选择——右侧够放（`innerWidth - parent.right >= width + 8`）即右，否则翻到左侧（宠物贴近右缘的默认右下停靠位即翻左）。定位通过直接写卡片的 style（transform + max-height）完成，与状态装饰相同的直接 DOM 写法；CSS 只保留测量前的兜底。因此无论宠物位置、尺寸或卡片页面，卡片都不会进入精灵上方的气泡带或下方的悬浮面板带。

## Alternatives considered

- **保留向上卡片并横向偏移**：冲突本质是纵向（卡片高于精灵），横移只在气泡较窄时有效；状态气泡有意做宽，此方案堵不住缺陷。
- **把向上卡片钳制到精灵高度**：卡片仍整体盖在精灵画面上，且其顶部正好落在气泡区内（气泡紧贴精灵顶边），药丸还是会被压。
- **侧面打开但不做高度钳制**：比精灵高的卡片居中后会同时越过两条带区，在最忙的页面（商店网格）重新引入重叠。

## Consequences

玩法卡片与宠物气泡/面板在任何停靠位置、任何卡片页面下都不再互相遮挡；卡片内容高于精灵高度时内部滚动（约 200px 以下宠物的商店页常见）。定位在 float 的局部坐标系内，拖拽宠物时卡片跟着走；卡片打开期间窗口 resize 会重选侧向。客户端 bundle 需重新构建后变更才能到达浏览器。

## Testing

包级 typecheck/test/build 通过；两个定位测试 mock 了 float 与卡片矩形（右侧有空间：`translate(168px, -80px)`、max-height 160px；贴右缘翻左：`translate(-248px, -80px)`）。http://127.0.0.1:3080 实机验证：卡片测得位于精灵左侧（206x154，落在 160px 精灵带内，垂直居中偏差 1px），上方状态气泡与下方悬浮面板均完全不受遮挡；侧向由位置决定，右下停靠位通常表现为卡片在左侧。
