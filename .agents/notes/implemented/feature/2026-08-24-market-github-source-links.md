# Agent Note: Market GitHub source links for skins and plugins

Status: implemented

## Problem

The Workshop (dsh-market.com site and the in-GUI Workshop card) offered no way to reach the GitHub source of a skin or a plugin: plugins had a repository line in the detail dialog, but card names were not links, and skin catalog items carried no repository field at all, so clicking a skin or plugin name could not open its repository (issue 1120).

## Decision

Treat the manifest field `repo` as the uniform source-repository link for skins and plugins across both surfaces. Every skin links either to its explicit `sourceUrl` or to its catalog directory in this repository:

- `scripts/market-build` mirrors an explicit v2 `skin.json` `sourceUrl` into `market/dist/manifest/skins.json` `repo` verbatim; when a skin has no explicit source, the generator links to that skin's catalog directory in this repository. Plugin `repo` values flow from `community.json` unchanged and are only emitted when declared.
- Market site (`market/src/app.js`): skin and plugin card names with a `repo` render as external anchors, with hover styling in `market/src/index.html`; the skin detail dialog gains the same 源码仓库 line the plugin dialog already showed. Repo-less items stay plain, and pet cards stay non-links (pets declare no repo).
- GUI card (`@linxin666/dsh-client-ui-market`): skin and plugin card names with a `repo` become external anchors; the existing footer 源码仓库 link now covers skins as well. Repo-less items stay plain.
- Clickable domain: the shared `PluginSettingsCard` chrome gains an optional `descriptionNode` rendered instead of the plain `t(descriptionKey)` header text (the plain text stays as the tooltip); the Workshop card passes a node wrapping `dsh-market.com` in a link to `https://dsh-market.com` (issue 1120 addition). All eight consumer copies are regenerated by `scripts/sync-shared.mjs`.

## Constraints

- Pets are excluded (issue scope is skins and plugins).
- No new schema or manifest file: the v2 `skin.json` schema already declares `sourceUrl`; market-build only mirrors it into the market manifest.
- Skins without a declared `sourceUrl` link to the catalog directory that owns their checked-in assets; explicit third-party source URLs remain authoritative.
- All links open in a new tab with `rel="noopener"`/`noreferrer`; the installer trust model is untouched (repo links are display-only, never install sources).
- The GUI catalog shape is unchanged apart from the additive `repo` field; `MarketRecord.repo` already existed.

## Alternatives considered

- Leaving repo-maintained skins without a link: rejected because the issue asks users to discover the corresponding GitHub source for every skin, and the catalog directory is the owning source when no distinct `sourceUrl` is declared.
- Setting per-skin `sourceUrl` in all 19 `skin.json` files: more explicit but hand-copies the repository origin into every manifest; rejected because the generator already knows the owning catalog path and can preserve distinct contributor URLs when present.
- Linking only the plugin detail dialog: rejected — the issue explicitly asks for name-level jumps on both surfaces.

## Acceptance criteria

- Every `skins.json` item has an https `repo`: it mirrors `skin.json` `sourceUrl` when declared, otherwise it points to the matching catalog directory (enforced against skin sources in `scripts/market-layout.test.mjs`). Plugin `repo` values (when present) stay https.
- `packages/dsh-market/tests/market-card.spec.tsx` asserts skin/plugin name links, the skin footer repository link, and the clickable `dsh-market.com` header description; `scripts/market-layout.test.mjs` asserts fallback catalog URLs for skins without an explicit source URL.
- `node scripts/market-build --check`, `node scripts/sync-shared.mjs --check`, `pnpm test:scripts`, and `pnpm --filter @linxin666/dsh-client-ui-market` typecheck/test/build all pass.
