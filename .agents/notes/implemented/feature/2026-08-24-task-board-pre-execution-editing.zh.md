# Agent Note: 执行前任务内容编辑

Status: implemented

## Problem

任务看板创建任务后只能查看任务内容，在第一次执行前无法修正标题、描述或执行 Prompt。若只在浏览器端增加编辑入口，旧客户端也可能在任务已经开始执行后继续修改内容。

## Decision

任务详情为仍在看板中、未运行且没有执行记录的任务提供标题、描述和执行 Prompt 编辑入口。编辑弹窗预填当前值，复用现有更新用例进行内容裁剪，并且只有 Host 确认更新后才关闭。Host 账本重复执行这条规则：运行中、已结算或启动后取消的任务收到内容 patch 时都 fail closed；工作区、模式和权限目标保持原有的未来执行编辑行为。已归档任务继续只读。

## Alternatives considered

- 只在浏览器端限制编辑：不取，因为并发或过期客户端仍可在执行开始后提交内容 patch；Host 账本是权威，必须在 Host 侧强制不变量。

- 第一次执行后把任务全部字段设为只读：不取，因为执行目标决定未来运行，现有行为允许非归档任务继续修改这些目标。

- 允许有过取消记录的任务再次编辑：不取，因为执行记录已经是一次启动尝试的持久记录，内容必须保持该次尝试原本计划执行的事实。

- 新增独立编辑页面而不是弹窗：不取，因为任务详情已经是唯一的变更入口，弹窗可以在不增加导航状态的情况下保留看板选择、校验和 Host 错误提示。

## Consequences

- 用户无需删除重建任务，就可以在执行前修正任务内容。
- 更新协议保持增量：内容字段继续使用现有 update action，Host 拒绝保护已执行历史不被过期客户端修改。
- Host 支持的 BoardController.updateTask 变为异步并返回权威是否接受 patch；旧的内存调用仍先同步应用状态，再返回已解析结果。
- 编辑界面复用任务看板现有表单样式和 locale key，不新增样式契约。

## Testing

任务看板包的 typecheck、测试套件和构建均通过；专项覆盖内容规范化、全新/运行中/已结算/启动后取消/归档状态的可编辑性、Host 拒绝与目标字段保留、协议解析以及 jsdom 编辑弹窗流程。
