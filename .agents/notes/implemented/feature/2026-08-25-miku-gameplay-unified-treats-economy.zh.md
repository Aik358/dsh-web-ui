# Agent Note: Miku 玩法统一为小鱼干经济（移除钱包）

Status: implemented

## Problem

miku 玩法此前跑着两套互不相干的货币。面板上的小鱼干库存服务于摸头/喂食经济（完成轮次与挂机时长发放、上限 20 条、喂食消耗），而玩法块另有自己的金币体系：`work` 成功 +3 金币 / 失败 -1、`passiveIncome` 1 金币/分钟、商店以金币计价还带一枚金币换游戏币的兑换券、彩票奖品档位最高 100 万金币。金币唯一露面的地方就是钱包页——商店被刷金币卡住、喂食小鱼干与购物毫不相关，钱包本身也是没有任何画面引用的多余页。

## Decision

玩法经济现在只跑一种货币——共享的小鱼干库存——钱包被移除。

- 客户端：删除 `wallet` 页、钱包按钮、`.gameplayWallet` CSS 与 `pet.gameplay.wallet` / `currency.coins` / `currency.gamecoins` 文案键；`PetGameplayStateView` 去掉 `currencies`（小鱼干走面板库存，不进视图）；商店成为唯一金钱界面，价格显示为小鱼干/Treats。
- 宿主桥接：引擎保留通用货币记录作为惰性结算工作区；`service.ts` 在每次玩法动词后把 `treats` 键抽干进共享账本（`grantTreats` 按库存上限截断，`spendTreats` 负担不起时拒绝）。`currency: "treats"` 的商店商品从 `ledger.snapshot.treats.treats` 校验并扣款；小鱼干彩票奖品按同一上限入账。旧数据里的金币/游戏币不再显示也不再被使用（引擎路径保持通用，无人消费）。
- 清单（miku）：`work` 成功 +1 小鱼干、失败不扣；`passiveIncome` 1 小鱼干/30 分钟；商店：黄油面包 2 条、红豆沙包 4 条、删除游戏币兑换券、彩票 3 条一抽、奖品为 5/10/20/50/100 小鱼干（沿用原概率）。market dist 已从 `assets/miku` 重新生成；已安装的 `$DSH_HOME/pets/miku` 副本已同步（注册表在插件启动时加载一次，宿主侧下次重启服务后生效）。
- 文档：README 对的玩法段落改写为统一货币与无钱包的菜单卡表述。

## Alternatives considered

- **保留金币引擎只让它隐形（钱包没了、金币继续累计）**：金币会变成没有出口也没有视图的静默流水，打工奖励无意义而商店却花小鱼干——否决。
- **连同金币一起删掉打工奖励、被动收入与彩票**：更轻，但小游戏会失去赚取循环和彩票的娱乐性；以小鱼干为唯一货币能同时保住两者。
- **商店改小鱼干但保留金币奖励**：仍是两套竞争的经济，商店被小鱼干上限卡住而金币闲置——否决。

## Consequences

一条余额（上限 20）现在同时养活喂食、购物与奖励：打工成为主要收入，彩票受库存上限约束（奖品大于上限会被截断），商店可以直接用面板现有库存结账。玩法状态视图变小（无 currencies）；旧持久化数据里的金币原样保留（无害、不可见）。客户端行为随 bundle 刷新生效；宿主清单与数据变更需重启一次服务（注册表启动时加载一次）。工坊 market dist 已重新生成；已安装的 miku 副本已为该重启同步。

## Testing

账本单测覆盖新增/消费的上限截断与负担不起的拒绝；路由规格（真实 HTTP 路由、全新服务）改写为小鱼干流程：空库存不足、打工赚到 20 上限、买面包花 2 条且饱食 +40、彩票花 3 条中 5 条（截断回 20）、持久化显示玩法货币为空而小鱼干在共享账本中。客户端测试覆盖无钱包卡片（任何地方都没有「钱包」、商店导航）与「小鱼干不足」/「中奖 +5 小鱼干」浮层。包级测试 434 通过。实机验证（bundle 刷新后）：钱包消失、无页面错误；商店仍展示重启前的旧清单（旧价格、缺失文案键退化为键文本）——清单与购买路由需宿主重启后生效。
